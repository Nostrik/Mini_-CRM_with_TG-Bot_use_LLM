# Развёртывание: бот и CRM в одном контейнере

Бот и Streamlit работают с одним файлом SQLite, поэтому запускаются **в одном контейнере** командой `python start.py`, а база лежит на **постоянном томе**, смонтированном в `/data`.

```
контейнер
├── start.py ─┬─► bot.py        (Telegram, long polling)
│             └─► streamlit app.py  (порт $PORT)
└── /data  ◄── постоянный том: crm.db
```

## Правила, без которых не заработает

1. **Том на `/data` обязателен.** Без него `crm.db` исчезнет при перезапуске. `start.py` пишет предупреждение в лог, если `/data` не смонтирован.
2. **Одна копия сервиса.** Не масштабируйте до 2+ экземпляров: два бота с одним токеном конфликтуют, а SQLite рассчитана на один хост.
3. **Не запускайте локально бота с тем же токеном**, пока он работает на сервере: Telegram разрешает только одно подключение на токен (в логах увидите повторы «Sleep for 1 seconds and try again»). Для локальной разработки создайте второго тестового бота у @BotFather.
4. **`.env` в образ не попадает** (он в `.dockerignore`). Все переменные задаются в настройках хостинга.

## Переменные окружения на хостинге

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `OPENROUTER_API_KEY` | ключ OpenRouter |
| `OPENROUTER_MODEL` | например `poolside/laguna-s-2.1:free` |
| `OPENROUTER_FALLBACK_MODELS` | например `nvidia/nemotron-3-super-120b-a12b:free` |
| `ADMIN_API_KEY` | длинная случайная строка (нужна для регистрации первого администратора) |
| `ADMIN_CHAT_ID` | ваш chat_id для уведомлений «бот запущен» (необязательно) |
| `APP_TZ` | например `Europe/Moscow` |
| `DB_PATH` | `/data/crm.db` (уже задан в Dockerfile, менять не нужно) |
| `PORT` | задаёт хостинг; если не задаёт, используется 8501 |

## Шаг 0. Проверка локально (по желанию)

Нужен установленный Docker.

```powershell
docker compose up --build
```

Откройте http://localhost:8501. Том `crm-data` создаётся автоматически, поэтому база переживёт остановку контейнера. Остановить: Ctrl+C, затем `docker compose down`. Значения в `.env` пишите без кавычек.

## Вариант 1. VPS с Docker Compose (самый предсказуемый)

На сервере должны быть Docker и плагин Compose (команда `docker compose version` должна работать).

```bash
git clone <ваш репозиторий> mini-crm && cd mini-crm
nano .env                       # переменные из таблицы выше (одним файлом, значения без кавычек)
docker compose up -d --build
docker compose logs -f          # убедиться, что бот и CRM запустились
```

CRM откроется на `http://IP-сервера:8501` (откройте порт 8501 в файрволе VDS). Данные лежат в томе `crm-data` и переживают перезапуски и обновления.

**Частые команды:**

| Что сделать | Команда |
|---|---|
| Обновить версию | `git pull && docker compose up -d --build` |
| Посмотреть логи | `docker compose logs -f` |
| Перезапустить | `docker compose restart` |
| Остановить | `docker compose down` (база сохраняется) |
| Состояние и healthcheck | `docker compose ps` |

**Осторожно:** `docker compose down -v` удаляет том вместе с базой лидов и пользователей.

### HTTPS на своём домене (рекомендуется)

По голому `http://IP:8501` пароли и заявки передаются без шифрования. Для боевого использования поднимите HTTPS:

1. Создайте у регистратора A-запись домена (например, `crm.example.com`) на IP сервера.
2. Откройте в файрволе порты 80 и 443.
3. Добавьте в `.env`:
   ```
   DOMAIN=crm.example.com
   BIND_ADDR=127.0.0.1
   ```
   `BIND_ADDR=127.0.0.1` закрывает порт 8501 снаружи: CRM будет доступна только через прокси.
4. Запустите с профилем `https`:
   ```bash
   docker compose --profile https up -d --build
   ```

Caddy сам получит и будет продлевать сертификат Let's Encrypt (конфигурация в `Caddyfile`), WebSocket для Streamlit проксируется автоматически. Адрес CRM: `https://crm.example.com`.

## Вариант 2. Платформа с поддержкой Dockerfile (Railway, Fly.io и подобные)

Общая схема одинакова, детали интерфейса смотрите в документации платформы:

1. Подключите репозиторий, платформа найдёт `Dockerfile`.
2. Создайте **постоянный том** и смонтируйте его в `/data`.
3. Добавьте переменные окружения из таблицы.
4. Убедитесь, что сервис запущен в **одном экземпляре**.
5. Включите публичный домен (HTTPS платформа выдаёт сама).

Платформа обычно передаёт порт в переменную `PORT`, `start.py` её подхватывает. Если платформа требует указать порт вручную, укажите 8501.

Перед выбором проверьте актуальные условия тарифа: бесплатные планы часто ограничены по времени работы, а доступность томов зависит от плана.

## Первый запуск

1. Откройте адрес CRM, перейдите на вкладку «Регистрация администратора», введите `ADMIN_API_KEY`, имя и пароль.
2. Во вкладке «Пользователи» создайте демо-пользователя с ролью «менеджер» для проверяющих и впишите его данные в отчёт.
3. Напишите боту и убедитесь, что лид появился.
4. **Рекомендуется** после создания администратора удалить `ADMIN_API_KEY` из переменных окружения и перезапустить сервис: регистрация новых админов по ключу отключится. Если доступ потеряете, верните ключ и зарегистрируйте нового администратора.

## Логи и место на диске

Что и сколько занимает место на сервере:

| Что | Где лежит | Чем ограничено |
|---|---|---|
| Файлы логов приложения | том `crm-data`, каталог `/data/logs` (`bot.log` и `crm.log`) | Ротация по размеру: файл до 5 МБ, хранится 5 старых, то есть не больше 30 МБ на процесс и около 60 МБ всего |
| Логи Docker (`docker compose logs`) | служебный каталог Docker | В `docker-compose.yml` ограничено: 3 файла по 10 МБ |
| Старые образы после пересборки | Docker | Не ограничено, чистить вручную (см. ниже) |

Лимиты логов меняются переменными окружения в `.env`: `LOG_MAX_MB` (размер файла, по умолчанию 5), `LOG_BACKUP_COUNT` (сколько старых файлов хранить, по умолчанию 5), `LOG_TO_FILE=0` (отключить файлы, оставить только консоль). Уровень логирования (INFO, DEBUG) задаётся константой `LOG_LEVEL` в `logger.py`. DEBUG пишет много, на сервере держите INFO.

Посмотреть свежие записи:

```bash
docker compose exec mini-crm tail -n 100 /data/logs/bot.log
docker compose exec mini-crm tail -n 100 /data/logs/crm.log
```

Каждая пересборка (`docker compose up -d --build`) оставляет старые образы. Раз в какое-то время чистите их:

```bash
docker image prune -f          # удалить неиспользуемые образы
docker builder prune -f        # очистить кэш сборки
docker system df               # сколько места занимает Docker
```

Команды `prune` не трогают тома, то есть базу и логи они не удаляют. Следить за общим свободным местом на сервере можно командой `df -h`.

## Резервная копия базы

Не копируйте `crm.db` просто так, пока приложение работает (рядом лежат файлы WAL). Консистентная копия:

```bash
docker exec mini-crm python -c "import sqlite3; s=sqlite3.connect('/data/crm.db'); d=sqlite3.connect('/data/backup.db'); s.backup(d); d.close(); s.close()"
```

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| CRM открывается, но выдаёт ошибку WebSocket или бесконечно грузится | Прокси не пропускает WebSocket. Включите поддержку WebSocket у прокси или платформы. В крайнем случае задайте `STREAMLIT_SERVER_ENABLE_CORS=false` |
| Бот молчит, в логах повторы «Sleep for 1 seconds» | Тот же токен используется ещё где-то (локально, второй экземпляр). Остановите лишний |
| После перезапуска пропали лиды | Том не подключён к `/data`. Смотрите предупреждение в логах при старте |
| «Регистрация администратора отключена» | Не задан `ADMIN_API_KEY` |
| Контейнер постоянно перезапускается | Смотрите логи: `start.py` завершается, если упал любой из процессов (чаще всего не задан токен бота или ключ OpenRouter) |
| Время в таблице в UTC | В образе нет часового пояса или задан неверный `APP_TZ` (образ включает `tzdata`) |
